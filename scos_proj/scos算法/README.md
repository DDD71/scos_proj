# SCOS 独立算法与分析包

按用户于 2026-11-03 确认的范围，采用六个业务包分别交付、分别验收，包内细分验收项。驾驶舱也作为独立包；全程追溯与质量协同作为第六包。六包是业务交付边界，不意味着都使用优化求解器。

当前只建立包结构、独立构建元数据和验收清单，未实现算法、Schema、测试算例或 Java 算法服务。版本 `0.1.0-SNAPSHOT` 不表示已具备业务能力。顶层 POM 仅聚合构建，六包各自有独立 POM 和版本，不继承聚合 POM。

## 每个包的结构

```text
packages/<业务包>/
├── pom.xml                         # 独立 Maven 坐标、版本与依赖
├── src/main/java/com/scos/algorithm/<业务包>/
│   ├── api/                        # 公开计算接口，待定义
│   ├── model/                      # 输入、输出和值对象，待定义
│   ├── engine/                     # 算法实现，待实现
│   └── validation/                 # 输入及结果规则校验，待实现
├── src/test/java/                  # unit / contract / acceptance
├── src/test/resources/fixtures/    # inputs / expected
├── contracts/v1/                   # 待编写 JSON Schema
├── service/                        # 待实现 Java 服务适配
└── docs/acceptance.md               # 本包分项验收清单
```

使用 JDK 17 或 21、Maven 3.6.3+。在本目录执行 `mvn verify` 可聚合构建六包；执行 `mvn -f packages/inventory/pom.xml verify` 可单独构建库存包。发布坐标统一为 `com.scos.algorithm:scos-<业务包>:<本包版本>`，每包输出独立 JAR，实际发布时使用各自正式版本。当前 JAR 仅为工程骨架，不包含计算实现。


## 服务与计算边界

Java 后端负责认证授权、任务持久化、业务事务、流程审批和结果归档；各 Java 算法包负责各自计算。计算核心只接收明确输入、返回明确结果，不读取业务数据库，不写正式业务单据，不直接依赖其他业务包实现。计算核心为普通 Java JAR，Java / Spring Boot 包装层可将其发布为独立 HTTP 服务，首期可以在同一台算法服务器分别运行容器。

驾驶舱包负责自身指标、异常、健康度和情景比较计算，Java 的 dashboard/sandbox 用例负责跨包任务编排，调用库存、采购、要货及成本的已发布服务版本。驾驶舱包不复制其他包的模型；可使用经确认的固定结果夹具单独验收自身计算，跨包联动另做集成验收。

成本包负责成本所需的批次关系和成本传导。追溯包负责跨系统正反向追溯和质量影响范围。两者使用有版本的批次关系数据契约，不相互导入实现；优先从权威数据快照获得批次事实，避免建立两套互相矛盾的批次编号及关系。

包可以使用不同依赖与发布周期。优化求解器按 Java API、约束表达、许可证、部署平台和性能验证后选择；当前未引入求解器依赖。旧蓝图中的算法语言及绑定方案以本次用户“统一 Java 包”的要求为准，不保留其他语言运行时。指标分析、成本计算、图遍历不强制依赖求解器。算法包版本、模型版本、契约版本及服务镜像版本分别记录。

## 其他候选包核对

- **沙盘**：蓝图场景 002，归驾驶舱包，包内单列验收；已有 Java sandbox 模块仍承担编排。
- **精益排程**：场景 004 为引用项，按当前技术蓝图不在本期实现，通过外部计划/MES 接口消费结果。
- **需求预测、价格预测**：当前材料不足以单独承诺预测模型交付；采购使用需求基线，行情提报不等于已经建设价格预测算法。若新增模型要求，再独立立项。
- **认证、审批、任务、文件、审计、外部系统适配**：属于 Java 平台或集成能力，必须验收，但不混入业务算法包。当前不新增巨大 shared 算法包；出现稳定复用后再提取、独立版本管理。

验收规则见 [分批验收与交付](docs/acceptance-policy.md)。包编号不是交付先后顺序，具体先后由业务优先级和数据准备情况确定。
