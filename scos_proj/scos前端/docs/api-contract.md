# 接口与数据状态约定

## 当前示例契约

仅驾驶舱提供适配器示例：

```text
GET /api/v1/dashboard/overview
```

```json
{
  "snapshotAt": null,
  "metrics": [{ "key": "sales", "label": "销售金额", "value": null, "unit": "万元" }]
}
```

这是待联调的客户端契约，并非已经存在的服务器接口。成功响应暂按直接返回业务 JSON 处理，后续以 OpenAPI 为准；若后端使用统一 envelope，在 HTTP 适配器中解包，不让页面依赖网络格式。

`null` 表示尚无数据，不能改成 `0`。`snapshotAt` 表示业务快照时间，不能使用浏览器当前时间伪装为数据刷新。

## 后续接口设计要求

- 查询使用服务端分页及明确的筛选参数；`PageResult<T>` 是暂定公共视图类型。
- DTO 与页面模型分开，单位、精度、枚举和时间在 `api/` 转换并校验。
- 计划关联以 ID、版本及快照标识进行，避免重复读取时得到不一致数据。
- 审批、发布和锁定由服务端状态机决定，写接口携带预期版本和幂等标识；前端不乐观伪造审批通过。
- 优化任务提交后返回任务标识；运行、失败、无解与取消是不同结果，不用定时器模拟成功。
- 同源请求通过 `/api` 反向代理；统一认证、CSRF、组织上下文传递方式须与后端确认，当前不假设已接入。
- 生产模式接口不可达时展示错误，禁止自动加载 Mock。错误响应可提供 `X-Request-ID` 便于定位。

## Mock 使用

只在 `mocks/` 中放样例。真实与样例适配器共同实现模块的 repository 接口，入口选择由 `VITE_DATA_SOURCE` 决定。开发默认 Mock；生产默认 HTTP，并在生产构建阶段拒绝显式 Mock。

原 Demo 的日期、供应商、成本和履约数据属于演示快照，不应直接升级为正式主数据。需要迁移样例时复制到新工程、标注来源及版本，避免运行时依赖旧目录。
