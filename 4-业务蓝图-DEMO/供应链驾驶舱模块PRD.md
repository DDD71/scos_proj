## 1. 产品概述

### 1.1 需求来源与依据

本 PRD 依据标书《SCOS 全局供应链优化与协同系统技术要求》编写，与标书条款的对应关系如下：

| 标书条款 | 内容 | 本 PRD 章节 |
|---|---|---|
| 第 1.3.2 节·模块概述 | 战略决策与指挥中枢，一站式视图 | 1.2、1.3 |
| 第 1.3.2 节·核心设计原则 | 角色导向/数据驱动/可视化/钻取溯源/智能预警 | 2、6、4.6 |
| 第 1.3.2 节·核心功能（1）全局态势总览 | 核心 KPI 卡片 | 4.1、5.1 |
| 第 1.3.2 节·核心功能（2）全局供应链地图 | GIS 地图 + 在途车辆 + 颜色编码 | 4.2 |
| 第 1.3.2 节·核心功能（3）专题分析子视图 | 销售/库存/生产/采购/经营五视图 | 4.3、5.2 |
| 第 1.3.2 节·核心功能（4）智能预警与事件管理 | 分级预警 + 联动 | 4.4 |

| 第 1.3.2 节·对投标方交付物要求 | KPI 清单/UIUX/自定义配置 | 5、6、4.7 |

### 1.2 产品定位与目标

供应链驾驶舱是 SCOS 的**战略决策与指挥中枢**，位于功能分层的「第一层：数据基石与决策中枢」。它不是独立的数据采集系统，而是基于其他模块（采购、库存、排程、成本、追溯）的**数据和运算结果**，通过多层级、可配置、可视化的方式，为管理层至执行层提供全局供应链状态的"一站式"视图。

驾驶舱要达成三个核心目标：

1. **态势感知透明化**：将"产销—储运—环保—资金"各环节的运行状态实时、统一地呈现，消除信息孤岛。
2. **决策支持数据化**：所有指标由系统数据自动计算、实时/准实时更新，为战略与战术决策提供量化依据。
3. **异常响应实时化**：主动识别并预警异常，支持从预警一键钻取到根因，快速发起处置，最终支撑"产销—储运—环保—资金"的**实时闭环管理**。

### 1.3 范围与边界

**模块包含（In Scope）**：

- 全局态势总览视图（核心 KPI 卡片）
- 全局供应链地图（GIS 地图、供应商/工厂/客户节点、运输路线与在途信息）
- 专题分析子视图（产销 / 储运 / 环保 / 资金）
- 智能预警与事件管理中心（分级预警、预警联动）
- 情景模拟与决策支持（沙盘推演）
- KPI 与看板的钻取溯源
- 个性化看板自定义配置（拖拽式）
- 移动端核心 KPI 监控与预警推送

**模块不包含（Out of Scope）**：

- 数据的采集、清洗与存储管道（由统一数据服务层 / 实时数据平台承担，见标书第四章、第六章）
- 优化模型的计算引擎（排程、采购、库存、成本等计算由各自模块承担，驾驶舱只消费结果）
- 主数据、事务数据的录入维护（驾驶舱只读展示，杜绝手工录入指标）
- 预警规则的业务触发逻辑归属各业务模块，驾驶舱负责**集中展示、分级与联动跳转**

### 1.4 产品原则

1. **角色导向**：提供可自定义视图，满足上级管理公司领导、总经理、总监、工厂调度员等不同角色的关注点。
2. **数据驱动**：所有指标必须由系统数据自动计算、实时/准实时更新，杜绝手工录入。
3. **可视化优先**：综合运用图表、图形、地图、颜色编码和动画，使复杂数据易于理解。
4. **钻取溯源**：支持从 KPI 总览到明细业务数据的逐层钻取，快速定位问题根源。
5. **预警与溯源**：实时识别异常，支持从指标或预警逐层钻取根因并追溯业务源单。

## 3. 信息架构与导航

驾驶舱作为 SCOS 的默认首页（决策中心下的首个模块），采用以下信息架构：

```
供应链驾驶舱
├── 顶部：五类指标总览（销售 | 库存 | 生产 | 采购 | 经营，共 20 项）
├── 中部左：全局供应链地图（GIS）
├── 中部右：实时预警中心（迷你预警面板）
├── 中部下：多维运营分析（标签页：销售 | 库存 | 生产 | 采购 | 经营）
├── 下部：智能预警中心（全量预警面板）
├── 下部：情景模拟推演（沙盘推演）
└── 全局：数据更新时间、刷新、导出报告、个性化配置入口
```

**导航交互规则**：

- KPI 卡片、地图节点、预警条目均为**可点击**元素，点击进入对应钻取视图或模块。
- 「销售 / 库存 / 生产 / 采购 / 经营」五个标签页可自由切换；支持用户将某个专题视图"固定"为默认页。
- 顶部提供「保存策略」「导出报告」「个性化配置」等全局操作入口。

## 4. 功能需求

> 优先级说明：P0 = 必须（标书底线要求）；P1 = 重要；P2 = 可选增强。

### 4.1 全局态势总览视图（五类指标）

**功能描述**：在界面顶部按销售、库存、生产、采购、经营五大业务域集中展示核心实时指标，让管理层在数秒内掌握端到端经营态势。

**五类指标（P0）**：系统必须预置以下 20 项指标，并支持后续配置扩展：

| 类别 | 指标 |
|---|---|
| 销售 | 销量、销售金额、在手销售合同量、在手销售合同金额 |
| 库存 | 成品库存量、成品库存周转天数、原料库存量、原料库存周转天数 |
| 生产 | 生产计划达成率、生产一次合格率、生产成本 |
| 采购 | 采购量、采购成本、在手采购合同量、在手采购合同金额、原料准时交货率 |
| 经营 | 营收、成本、利润、现金循环周期 |

**交互与展示要求**：

- 每项指标展示：指标名称、当前值、环比/同比变化（▲/▼ + 变化量），变化方向根据业务语义标色；成本、周转周期等“越低越优”指标采用反向语义。
- 五个业务域通过顶部标签切换，内容区不再重复展示业务域名称和指标数量；所选业务域的指标卡片直接使用完整内容宽度。
- 演示数据约束：原料库存量不高于 2,000 吨，原料库存周转天数不高于 1.5 天；总览、钻取、导出及专题分析中的同口径数据必须保持一致。
- 五类指标组按角色可配置显示顺序与显隐；点击任一具体指标进入该指标的钻取分析视图。
- 数据更新频率：关键运营类 KPI ≤ 5 秒（详见 8.1）。

**验收要点**：五类共 20 项指标均自动计算、无手工录入；每项均展示当前值与变动并支持点击钻取；数据更新时间可见。

### 4.2 全局供应链地图（GIS）

**功能描述**：基于 GIS 地图，以太仓工厂为唯一生产中心，可视化展示指定玉米淀粉供应商、指定大客户及两段式运输网络。供应商—工厂线路反映原料入厂，工厂—客户线路反映成品履约；节点与线路支持悬停查看业务明细。

**详细需求**：

1. **节点分布展示（P0）**：地图只展示三类节点，并使用不同图标和颜色区分：
   - 工厂：仅太仓工厂；悬停展示工厂全称、日产能和运行状态。
   - 供应商：仅展示裕米生物科技(山东)有限公司、玉峰实业集团有限公司、河北德瑞淀粉有限公司、中粮生物科技（天津）有限公司-内部、山东福宽生物工程有限公司、京粮龙江生物工程有限公司、山东大泽成生物科技有限公司。地图标签使用简称，悬停展示完整名称和在手合同量。
   - 客户：仅展示福敬德、不凡帝、可口可乐、百事可乐、康师傅、超克、奇异鸟、冠生园、德凯、上好佳、味好美、联合利华。地图常驻展示业务名称，悬停展示客户主体全称和未履约销量。

2. **运输路线（P0）**：
   - 每家供应商分别连接太仓工厂，形成原料入厂路线；每家客户分别由太仓工厂连接，形成成品配送路线。
   - 光标移动到线路时，展示路线类型、起点、终点、当前在途量和预计到达时间。
   - 原料入厂与成品配送使用不同颜色，线路带方向动画；当前版本不再单独展示仓库和在途车辆节点。

3. **地理位置口径（P0）**：

## 6. UI/UX 设计理念与交互规范

> 标书要求：阐述设计如何符合用户习惯、降低认知负荷。

### 6.1 设计理念

1. **一屏全局（Overview First）**：首屏用五类指标组 + 地图 + 迷你预警，让决策者在数秒内形成全局认知，细节随需下钻。
2. **颜色即语义（Color = Meaning）**：红/黄/绿三色贯穿健康状态、预警分级、趋势涨跌，统一语义，降低学习成本。
3. **减少认知负荷**：每屏信息密度适中，先总览后明细，避免信息过载；复杂数据用图表而非表格优先呈现。
4. **钻取而非跳转（Drill, Don't Switch）**：尽量在驾驶舱内完成钻取，减少跨模块页面切换与人工核对。
5. **角色适配（Role-based）**：默认视图按角色裁剪，只展示该角色关心的数据，减少干扰。

### 6.2 视觉规范（与现有原型一致）

- **主题**：深色科技风（dark theme），以蓝、青、绿、黄、紫区分指标类别。
- **KPI 卡片**：五色区分（蓝=产销、青=库存、绿=交付、黄=成本、紫=资金）。
- **图表引擎**：ECharts（地理坐标、雷达、柱线、饼图、热力图等）。
- **字体/密度**：数据用等宽字体（JetBrains Mono/Orbitron 风格），保证数字可读性。
- **表格对齐**：系统配置、驾驶舱、沙盘推演、库存优化、采购优化、要货计划、生产排程、成本分析和追溯等全部模块采用统一表格规范；表头与对应数据单元格均水平居中、垂直居中，数值、状态、日期和操作列不得使用与表头不一致的对齐方式。表格内输入框、下拉框、按钮组、标签及“主值+辅助说明”复合字段以单元格中心线为基准对齐。

### 6.3 交互规范

| 交互 | 规范 |
|---|---|
| 数据刷新 | 顶部显示"数据更新于 HH:MM"，提供手动刷新按钮 |
| 全局操作 | 保存策略、导出报告、个性化配置置于顶部统一入口 |
| 悬停提示 | 图表 hover 显示 tooltip 明细 |
| 空/异常态 | 数据缺失或异常时显示明确占位与提示，不展示误导性数据 |

## 7. 数据与接口需求

### 7.1 数据获取原则

- 驾驶舱**只消费**统一数据服务层 / 实时数据平台提供的标准数据，自身**不包含**独立的数据采集、清洗、存储管道（标书第四章、第六章）。
- 所有指标由系统数据自动计算，杜绝手工录入。
- 与底层数据平台及其他业务模块通过 **RESTful API** 交互，确保数据完整性与一致性。

### 7.2 核心接口

| 数据/能力来源 | 接口方式 | 提供给驾驶舱的内容 |
|---|---|---|
| 统一数据服务层 | RESTful API | 主数据、交易数据、聚合分析数据（KPI 基础数据） |
| 实时数据平台 | 消息订阅 | 产量、发货量、储罐液位、产线状态、车辆位置等实时指标 |
| 采购/库存/排程/成本/追溯模块 | RESTful API / 事件总线 | 各模块计算结果与预警事件 |
| SAP | API | 财务、资金、成本类指标（权威数据源） |
| 数字孪生 / 厂区管理平台 | 专用 API + 事件流 | 空间元数据、业务态势流（三维可视化联动） |

### 7.3 数据一致性

- 资金类数据权威源明确指定为中粮 SAP 系统，与 SAP 的财务数据同步逻辑、频次及对账机制需在设计中说明并经甲方确认。
- 驾驶舱展示的指标与各业务模块输出保持同源一致，避免口径分歧。

## 8. 非功能性需求

### 8.1 数据实时性

| 数据类型 | 更新延迟要求 |
|---|---|
| 关键运营类 KPI（产量、发货量、库存、在途状态） | ≤ 5 秒 |
| 战略分析类数据（成本、资金、账龄） | ≤ 1 小时 |

### 8.2 性能要求

| 指标 | 要求 |
|---|---|
| 主要视图首次加载 | ≤ 3 秒 |
| 数据钻取响应 | ≤ 2 秒 |
| 并发用户 | ≥ 50 个并发用户在线操作 |
| 数据规模 | 支持 5 年内累计 TB 级业务数据，性能无明显衰减 |

### 8.3 安全与权限

- 严格基于角色与组织的精细化访问控制，支持到功能菜单、操作按钮及**数据行/字段级别**。
- 支持与中粮上级管理公司现有统一身份认证系统集成。
- 所有操作留痕，审计日志不可篡改，保留不少于 2 年。

### 8.4 移动端与可用性

- 核心 KPI 监控与预警推送提供移动端友好访问（手机、平板）。
- 界面直观简洁，符合业务操作流程；支持可配置、可拖拽的个性化仪表盘。

### 8.5 可靠性与业务连续性

- 系统 7×24 小时可用，整体年可用性 ≥ 99.7%。
- 当与部分外部系统（供应商门户、第三方地图服务）连接中断时，核心监控与预警应能**降级运行**或基于最新缓存数据继续工作（地图服务中断时，保留节点列表与预警展示）。

## 10. 待确认事项与风险

### 10.1 待确认事项

1. **资金类数据口径**：现金循环周期（DSO/DPO）、供应链总运营成本的归集口径与 SAP 的映射关系，需与财务及 SAP 实施方对齐。
2. **地图与数字孪生边界**：驾驶舱 GIS 地图与"数字孪生及厂区管理平台"三维可视化的分工与集成深度，需明确是轻量二维地图还是复用数字孪生引擎。
3. **预警分级阈值**：一级/二级预警的具体业务阈值（如安全库存倍数、能耗超标百分比）需由业务方确认并在规则引擎配置。
4. **角色默认视图**：上级管理公司领导的具体可见范围与指标集合，需与甲方统一身份认证系统角色映射确认。
5. **移动端推送渠道**：预警推送采用 APP 推送/短信/邮件中哪一种或组合，需确认。

### 10.2 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据源接口未就绪 | 指标无法自动计算 | 提前确定统一数据服务层接口清单，驾驶舱做数据缺失降级展示 |
| 实时数据延迟不达标 | 关键 KPI 超过 5 秒 | 采用消息订阅 + 缓存，关键指标走实时数据平台专用通道 |
| 地图/第三方服务中断 | GIS 视图不可用 | 降级为节点列表 + 预警面板，核心监控不中断 |
| 成本/资金数据敏感 | 越权泄露 | 行级/列级权限 + 审计留痕 |
