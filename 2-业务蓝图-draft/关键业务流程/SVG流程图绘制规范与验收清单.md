# SVG 流程图绘制规范与验收清单

## 1. 文档目的与适用范围

本文档用于统一关键业务流程 SVG 的绘制、优化和交付标准，重点解决不同流程图之间的样式不一致、泳道文字越界、节点与连线重叠、回线绕行过多、箭头缺失以及输出物与连线交叉等问题。

本文档仅关注 SVG 流程图的图形表达和技术验收，不涉及业务需求梳理、Markdown 正文编写、节点说明表或 Visio 交付规范。

## 2. 参考基准与核心原则

### 2.1 样式基准

- 后续流程图默认参照已确认的《业务蓝图_月度采购方案制定流程_优化.svg》。
- 若用户另行提供新的参考图，以最新明确确认的参考图为准。
- 复用的是视觉语言和排版规则，不得因为套用样式而改变当前流程的业务节点、角色归属或分支逻辑。

### 2.2 总体原则

1. 业务流程不变时，只调整样式、布局和连线，不增删或改写业务含义。
2. 流程图宽度不做机械限制，应优先保证节点、连线和标注清晰，避免为压缩画布而制造交叉。
3. 一张图应有唯一的“开始”和唯一的“结束”节点；各终止分支统一连接至最终的结束节点。
4. 节点和连线应尽量不交叉，连线不得穿过不相关节点、文字、系统标签或子数据节点。
5. 在业务逻辑一致的前提下，优先使用最短、最直观、拐点最少的连线。
6. 所有流程节点的入口必须具有完整、清晰的箭头；所有节点、连线及非汇流线路之间不得发生交叉或非必要重叠。

## 3. 画布与基础视觉规范

### 3.1 画布和外框

- 使用白色背景和细灰色外框，不使用渐变、阴影、纹理或装饰性背景。
- 画布高度可参考 860px，宽度根据流程复杂度扩展，不强制压缩至固定比例。
- 顶部设置带完整外边框的流程标题区，标题格式为“流程编号及名称：（流程编号 流程名称）”。
- 标题区必须使用白色填充和四边完整的细灰色边框；标题框左右边界应与下方流程主体外框对齐，标题框底边与流程主体外框顶边连续衔接，不得只保留标题文字而缺失外框。
- 标题区、泳道分隔线和节点边框均使用细灰线；主流程连线使用黑色实线。
- 图底部可保留业务口径说明，但不额外绘制与参考样式不一致的独立说明表格或分隔行。

### 3.2 字体

推荐使用以下 SVG 字体规则：

| 用途 | 字体 | 字号 | 其他要求 |
|---|---|---:|---|
| 流程标题 | SimSun、Songti SC、STSong、serif | 23px | 字重 600 |
| 泳道名称 | SimSun、Songti SC、STSong、serif | 常规 18px；空间不足时 15px | 居中、纵向排列 |
| 节点文字 | SimSun、Songti SC、STSong、serif | 16px | 水平居中 |
| 分支及辅助说明 | SimSun、Songti SC、STSong、serif | 15px | 靠近对应线路 |
| 底部业务口径 | SimSun、Songti SC、STSong、serif | 14px | 深灰色 |
| 系统标签 | Arial、Microsoft YaHei、sans-serif | 14px | 白色、居中、不加粗 |

字体回退顺序应写入 SVG 样式，避免不同操作系统缺少首选字体时文字无法显示。

### 3.3 泳道

- 泳道按参与角色或系统从上到下排列，节点必须放在实际执行主体对应的泳道中。
- 左侧泳道名称统一采用逐字符纵向排列，禁止同一张图中部分横排、部分竖排。
- 中英文混合名称也应逐字符排列，例如 E采/SAP、供应商/TMS、QMS/LIMS 中的英文字母分别占一行。
- 泳道名称必须在本泳道边界内，上下均保留安全间距，不得压线或跨入相邻泳道。
- 当泳道较矮或名称较长时，优先将字号缩小至 15px 并收紧行距，不应通过横排或越界解决。
- 泳道名称列应保持统一宽度，文字在列内水平居中。
- 泳道名称列宽度应按实际名称所需空间从紧设置，以能够完整容纳最长泳道名称并保留必要安全边距为准，禁止保留明显过宽的空白列。

### 3.4 节点与系统标签

- 开始和结束：使用白底灰边圆形。
- 业务处理：使用白底灰边矩形。
- 判断：使用白底灰边菱形，必须有清晰的分支出口。
- 业务单据或数据输出：使用底边波浪形的文档节点。
- 同一张图中的同类节点应使用一致的边框色、线宽、尺寸体系和文字样式。
- 系统标签放在节点左上角并与节点边框轻微重叠：
  - SCOS 使用蓝色标签；
  - 数据服务或外部系统使用绿色标签；
  - 标签文字必须完整、居中，不得超出色块。
- 节点编号建议按 10、20、30……递增；编号必须在节点内单独占用一行，置于业务动作文字上方，不得与节点名称或动作描述同行。

### 3.5 子数据节点和输出物

- 子数据节点用于表达关键输入、输出或业务单据，不代表新增流程步骤。
- 子数据节点的外形宽度和高度必须小于其父业务节点，不得与普通业务节点等大或更大；缩小外形时保持既定文字字号不变，并确保文字完整容纳。
- 子数据节点放在父节点右上方，并与父节点保持少量重叠；重叠面积不宜过大。
- 父节点与子数据节点之间不绘制连接线。
- 子数据节点应绘制在父节点之后，使其边框和白色填充自然覆盖父节点右上部分区域。
- 主流程连接线必须绕开子数据节点；必要时将转折点移至子数据节点右侧，并保留可见间距。
- 多个子数据节点并列时，应避免彼此遮挡，也不得侵入判断节点或相邻流程节点。

## 4. 连线、箭头与分支规范

### 4.1 基础连线

- 流程线统一使用黑色实线、直角折线和实心箭头。
- 每一个业务节点、判断节点、结束节点以及其他具有流程入口的节点，所有实际进入该节点的线路末端都必须显示完整箭头，不得遗漏任何中间节点或分支节点的入口箭头。
- 箭头尖端必须准确落在目标节点边界上，不得伸入节点内部或悬停在节点外。
- 每条带箭头的线路必须包含完整连线，禁止只显示箭头而缺少箭头前的线段。
- 禁止将多个需要分别显示入口箭头的连接段写在同一个 SVG `path` 的多个 `M` 子路径中；应拆分为独立带 `marker-end` 的路径，或确保每一个目标入口均单独绘制箭头。
- 起点应从节点边界发出，终点应落在目标节点边界；不得让线条从节点内部穿出。
- 连线应尽量沿水平或垂直方向进入节点，避免斜线和不规则折线。

### 4.2 拐点控制

- 每个拐点都应有明确的避让或跨泳道作用；没有必要的拐点必须删除。
- 能够直接向上、向下、向左或向右连接时，不增加“先绕开、再折返”的线路。
- 若线路只需“水平到目标正下方，再垂直进入节点”，不得额外增加左右绕行。
- 调整线路后应重新检查整个路径，避免局部优化造成新的交叉。

### 4.3 判断分支

- 判断节点使用菱形，并为所有业务分支绘制完整出口。
- Y、N 或分支说明应放在对应出口附近，不能与节点文字、系统标签、箭头或泳道边界重叠。
- 分支文字必须与实际走向一致，不得出现图上标注了 N 但没有对应连线的情况。
- 判断后的分支应尽早拉开，避免两条线路在判断节点附近提前重合而难以识别。

### 4.4 返回线和回线

- 返回线优先从判断节点的上方、下方或外侧直接返回目标节点，选择最短且不穿越节点的路径。
- 返回上方节点时，如果纵向直接连接即可，不应先向左或向右绕出多个拐点。
- 回线不得穿过父节点、子数据节点、判断菱形、系统标签或文字说明。
- 多条返回线可以共用进入同一目标节点的最后一段，但在此之前应保持各自线路可辨识。
- 汇流前的支路使用无箭头线段；共用的最后一段只绘制一次，并只保留一个箭头。

### 4.5 多分支汇流

- 多条业务路径最终进入同一节点时，优先在靠近目标节点的位置汇流。
- 不要在前置判断节点之前提前合并，否则会削弱分支来源的可读性。
- 若两条线路从不同方向接近目标节点，应分别绘制到汇流点，再由一条共用线进入目标节点。
- 若分别从不同边进入目标节点更清晰，也可以不汇流，但每条线路必须有独立、完整且不重叠的箭头。
- 禁止在完全重合的路径上重复绘制两条线或两个箭头。

### 4.6 交叉和重叠避让顺序

- 节点与节点之间不得交叉或非必要重叠，父节点与其右上方子数据节点的规范性少量重叠除外。
- 连线与任何节点、系统标签、节点文字、分支说明或业务口径不得交叉。
- 不同连线之间不得交叉；确需进入同一目标节点时，应在目标附近明确汇流，共享最后一段线路，不得以交叉方式表达汇流。
- 发现交叉时必须调整节点位置、线路出口、路径层级或画布宽度，不能将交叉作为可接受结果保留。

出现空间冲突时，按以下顺序处理：

1. 删除不必要的拐点。
2. 调整转折点位置，使线路绕开子数据节点和文字。
3. 适当拉开节点间距或扩展画布宽度。
4. 调整分支从节点的不同边进入。
5. 仅在业务含义完全一致且来源仍可辨识时，合并最后一段线路。

不得通过缩小全部节点、压缩文字或让线路穿过节点来解决空间冲突。

## 5. 底部业务口径格式

- 底部说明采用“业务口径：……”的单行文本格式。
- 业务口径必须放置在泳道主体外框以内的左下角，禁止放在泳道边框外部或画布外框之外。
- 文字从泳道名称列右侧开始，与流程内容区左边界保持统一缩进；文本基线应位于泳道外框底边上方，并保留清晰的内边距。
- 使用宋体优先字体栈、14px、深灰色。
- 不增加灰底、文本框、粗边框或与参考样式不一致的独立说明区域。
- 不在说明文字上方额外增加分隔线，除非最新参考图明确包含该分隔线。
- 说明文字不得与底部回线、分支标签或外框重叠；如空间不足，应优先调整回线高度或增加画布高度。

## 6. SVG 实现建议

### 6.1 样式集中定义

建议在 SVG 的 style 中集中维护以下类：

- title：流程标题；
- lane-text：泳道名称；
- node-text：节点文字；
- small-text：分支和输出物文字；
- note-text：底部业务口径；
- node：节点和文档边框；
- divider：泳道分隔线；
- flow：带箭头的流程线；
- flow-stem：不带箭头的汇流前线段；
- tag-scos、tag-external：系统标签色块；
- tag-text：系统标签文字。

禁止为每个节点重复写一套不同的行内字体和边框属性，以免后续修改时产生样式漂移。

### 6.2 箭头定义

- 箭头使用 marker 统一定义，所有流程线引用同一个 marker。
- marker 的 refX 应使箭头尖端落在路径终点，避免箭头进入目标节点。
- 汇流前线路不引用 marker；只有最终进入节点的共享线段引用 marker。

### 6.3 绘制顺序

推荐按以下顺序组织 SVG 元素：

1. 背景、外框和标题；
2. 泳道分隔线和泳道名称；
3. 开始、结束和业务节点；
4. 系统标签及节点文字；
5. 子数据节点和输出物；
6. 主流程、判断分支和返回线；
7. 分支标识及辅助说明；
8. 底部业务口径。

当需要让输出物覆盖父节点右上方时，输出物必须位于父节点之后绘制；同时应通过坐标避让，不能依赖遮盖隐藏错误的连接线。

## 7. 文件命名与修改范围

- 原始 SVG 默认保留，不直接覆盖。
- 优化版本与原文件放在同一目录，文件名增加“_优化”后缀，例如“业务蓝图_采购执行跟踪流程_优化.svg”。
- 若用户明确要求修改当前优化版，则在该优化文件上继续迭代，不额外生成多个难以识别的版本。
- 临时渲染文件和预览图片放入临时目录，不写入正式资产目录。
- 交付前确认 Markdown 或其他文档引用的文件名与实际文件一致。

## 8. 验证方法

### 8.1 XML 结构校验

使用以下命令确认 SVG XML 可解析：

    xmllint --noout "目标文件.svg"

校验通过仅代表结构合法，不代表布局正确。

### 8.2 原生渲染检查

在 macOS 上使用 Quick Look 生成缩略图：

    qlmanage -t -s 2500 -o /private/tmp "目标文件.svg"

渲染后必须查看图片，而不是只检查命令退出码。宽幅 SVG 可复制到临时目录并临时扩大画布高度，以避免 Quick Look 生成过窄预览；不得因此修改正式 SVG 的业务画布。

### 8.3 必须检查的视觉区域

- 左侧泳道名称，尤其是中英文混合长名称；
- 所有判断节点及 Y/N 分支；
- 返回上方节点的回线；
- 多分支汇流点和共享箭头；
- 每一个流程节点的所有入口，逐一确认箭头完整可见；
- 父节点右上方的子数据节点；
- 子数据节点与父业务节点的尺寸对比；
- 节点之间的垂直转折线；
- 全图所有节点—节点、连线—节点以及连线—连线的交叉位置；
- 最终结束节点及其所有入口；
- 泳道外框内左下角的业务口径与底部回线。

每次修改连接线、泳道文字或输出物位置后，都应重新渲染检查。

## 9. 交付前验收清单

### 9.1 样式

- [ ] 流程图与最新参考 SVG 的字体、配色、边框和节点形状一致。
- [ ] 标题格式、流程编号和流程名称正确。
- [ ] 标题区具有四边完整的细灰色外框，并与下方流程主体外框左右对齐、连续衔接。
- [ ] 泳道名称全部采用统一的纵向格式。
- [ ] 长泳道名称未越界、未压线、未混用横排。
- [ ] 泳道名称列已按最长名称从紧设置，能够容纳文字且无明显多余空白。
- [ ] 系统标签颜色、字号和位置统一。
- [ ] 底部业务口径格式与参考图一致。
- [ ] 业务口径位于泳道主体外框以内的左下角，并与边框保持安全内边距。

### 9.2 节点和输出物

- [ ] 开始和结束节点各只有一个。
- [ ] 业务节点和判断节点均位于正确泳道。
- [ ] 所有节点编号均在节点内独立成行，未与业务文字同行。
- [ ] 节点文字无溢出、无裁切、无碰线。
- [ ] 子数据节点位于父节点右上方，仅少量重叠。
- [ ] 每个子数据节点的宽度和高度均小于父业务节点，且缩小外形后文字字号未改变、内容未溢出。
- [ ] 子数据节点与父节点之间没有连接线。
- [ ] 子数据节点没有遮挡相邻节点或分支说明。

### 9.3 连线和箭头

- [ ] 所有连线均从节点边界发出并落在目标节点边界。
- [ ] 每一个节点的所有实际入口均有完整箭头，包括主流程中间节点、判断节点、分支节点和结束节点。
- [ ] 不存在只有箭头而缺少前置线段的情况。
- [ ] 箭头未伸入节点或与节点文字重叠。
- [ ] 连线未穿过节点、系统标签、文字或子数据节点。
- [ ] 节点之间、连线与节点之间、不同连线之间均不存在交叉或非必要重叠；规范性子数据节点重叠和明确汇流段除外。
- [ ] 无不必要的拐点和绕行。
- [ ] 判断节点的所有分支均有完整线路和清晰标注。
- [ ] 返回线走最短、直观且不交叉的路径。
- [ ] 多线路仅在必要的最后一段汇流。
- [ ] 共享线段只绘制一次且只有一个箭头。
- [ ] 最终所有终止分支均进入唯一结束节点。

### 9.4 技术和文件

- [ ] SVG 已通过 xmllint 结构校验。
- [ ] SVG 已通过 Quick Look 原生渲染检查。
- [ ] 修改连线或文字后已重新渲染。
- [ ] 正式文件无临时标注、红框或调试元素。
- [ ] 原始文件已保留，优化文件命名和目录正确。
- [ ] 交付链接指向实际存在的最终 SVG。

## 10. 常见问题与修正方式

| 问题 | 常见表现 | 修正方式 |
|---|---|---|
| 泳道名称越界 | 最后一个字符跨过分隔线 | 缩小至 15px、收紧行距并重新居中 |
| 中英文方向混乱 | 中文竖排，TMS、QMS 横排 | 英文字母也逐字符纵排 |
| 子数据节点被连线穿过 | 父节点出口的垂直线穿过文档形状 | 将转折点移到文档节点右侧并留间距 |
| 子数据节点过大 | 输出物与父节点等大或遮挡相邻流程 | 在不改变字体大小的前提下缩小外形，确保宽度和高度均小于父节点 |
| 中间节点入口缺少箭头 | 多个 `M` 子路径共用一个带 `marker-end` 的 `path`，只有最后一段显示箭头 | 将各连接段拆成独立路径，并逐一检查每个节点入口箭头 |
| 节点或连线交叉 | 回线穿过主线、节点互压或两条独立线路相交 | 调整节点位置和线路出口，扩展画布或在目标附近规范汇流，直至交叉完全消除 |
| 回线拐点过多 | 先向左绕行，再折回目标正下方 | 沿底部到目标正下方后直接向上 |
| 分支过早合并 | 两个判断出口在判断节点附近即重合 | 支路保持独立，只共用进入目标的最后一段 |
| 双线或双箭头 | 两条完全重合路径各自带箭头 | 汇流前改用无箭头线，最后一段只画一次 |
| 箭头压入节点 | 箭头尖端落在节点内部 | 调整 marker 的 refX 或路径终点 |
| 底部说明样式不一致 | 出现额外分隔行、字号或字体不同 | 对齐参考图的单行宋体 14px 深灰说明 |
| 业务口径位于泳道外 | 说明文字落在泳道底边以下 | 将业务口径移入泳道主体外框左下角，并预留底边和左侧内边距 |
