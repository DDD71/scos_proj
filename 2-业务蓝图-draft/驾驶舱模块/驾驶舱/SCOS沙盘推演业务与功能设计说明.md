# SCOS 沙盘推演业务与功能设计说明

## 1. 文档目的

本文档沉淀 SCOS 供应链驾驶舱沙盘推演的业务定位、功能范围、运行逻辑、输入输出、上游数据和模块协同关系，为后续编制业务蓝图、功能清单、数据蓝图和系统接口方案提供统一依据。

本文档以三个首期核心场景为范围：

1. 客户增单与交期变化；
2. 供应商到货延迟；
3. 生产能力下降。

沙盘推演是决策支持工具，不是正式计划编制和业务执行入口。

## 2. 建设依据

### 2.1 标书要求

《SCOS 全局供应链优化与协同系统技术要求》将供应链驾驶舱定位为战略决策与指挥中枢，并明确要求提供情景模拟与决策支持能力：用户可以修改关键参数，快速观察需求波动、供应风险等事件对全局供应链的影响。

标书同时要求：

- 驾驶舱基于其他业务模块的数据和运算结果工作；
- 供应链指标自动计算并支持钻取溯源；
- 采购模块能够进行供应商受限和供应风险情景分析；
- 生产排程模块能够响应设备故障、物料延迟和订单变化；
- 库存模块能够计算安全库存、再订货点并监控库存水位；
- 模型输入输出沙盒能够提供特定时点的数据和模型参数快照；
- 所有数据和模型调用应通过统一数据服务与标准接口完成。

## 3. 业务定位

### 3.1 解决的问题

日常驾驶舱用于展示当前状态和预警，沙盘推演用于回答“如果发生变化，会造成什么影响”。

沙盘需要回答以下问题：

1. 风险从哪个业务对象开始；
2. 风险如何在采购、生产、库存和交付之间传导；
3. 哪一天跌破安全线，哪一天可能缺料或缺货；
4. 哪些供应商、物料、产线、产品、计划和订单受到影响；
5. 与当前基线相比，服务、库存、产能和成本变化多少。

### 3.2 业务价值

- 将抽象风险转化为具体日期、数量和业务对象；
- 帮助管理人员在正式决策前理解潜在影响；
- 为采购、排程和库存业务人员提供跨模块共同分析口径；
- 支持不同参数条件下的结果比较；
- 保留完整的快照、参数和模型版本，支持复盘。

### 3.3 使用角色

| 角色 | 主要用途 | 权限范围 |
|---|---|---|
| 供应链总监 | 查看跨模块影响和关键风险日期 | 授权组织范围内全部场景和汇总成本 |
| 工厂总经理 | 查看交付、产能、库存和经营影响 | 本工厂汇总信息和授权成本信息 |
| 生产调度员 | 分析产能下降和订单变化影响 | 本工厂产线、产品、排程和库存信息 |
| 采购人员 | 分析供应商延期和原料缺口 | 授权供应商、物料、采购计划和采购成本 |
| 管理公司领导 | 查看多组织风险和指标变化 | 授权组织汇总结果，不默认查看敏感明细 |

## 4. 设计原则

### 4.1 控制变量

首期每个场景仅开放两个可调变量。客户、产品、供应商、物料和产线仅用于确定推演范围，不作为情景变量。

这样可以保证：

- 用户能够明确知道结果由哪些参数引起；
- 演示和业务解释简单；
- 场景之间便于比较；
- 降低多个变量共同变化导致的归因困难。

### 4.2 同源基线

每次推演必须绑定不可变的数据快照。基线与模拟结果使用相同的数据截止时间、组织范围、计划版本、模型版本和指标口径。

### 4.3 差量模拟

用户修改的参数只作为基线快照上的差量保存，不修改源订单、采购承诺、生产计划、库存策略和模型正式参数。

### 4.4 模型复用

驾驶舱负责情景管理、参数传递、模型编排和结果展示，不在驾驶舱内重新建设采购、排程或库存优化模型。

### 4.5 结果可解释

结果必须包含具体日期、影响对象、数量变化、指标差异和传导链。不得只展示综合评分或无法解释的结论。

### 4.6 只推演不执行

沙盘结果不采纳、不发布、不下发，不生成采购订单、生产工单或正式库存策略。需要采取业务行动时，用户退出沙盘并进入相应业务模块重新发起正式计算、确认和审批。

## 5. 总体业务逻辑

```text
选择场景模板
  → 选择组织和业务对象
  → 锁定基线数据快照
  → 修改两个情景变量
  → 执行参数和数据校验
  → 生成模型调用顺序
  → 调用业务模块模拟接口
  → 聚合库存、产能、交付和成本结果
  → 识别关键日期和受影响对象
  → 展示基线与模拟差异
  → 保存、比较或导出模拟结果
```

### 5.1 快照准备

系统向模型输入输出沙盒申请指定时间点的数据快照。快照至少包含：

- 组织和时间范围；
- 销售订单和需求版本；
- 采购订单和到货承诺版本；
- 生产排程和产能日历版本；
- 成品库存策略和库存状态版本；
- 成本口径和费率版本；
- 模型和参数版本；
- 数据截止时间和质量状态。

### 5.2 参数覆盖

用户只调整当前场景允许修改的两个参数。系统保存基线值、模拟值、差量、单位、对象和修改人。

### 5.3 校验

运行前校验：

- 用户是否具有组织和对象权限；
- 客户、供应商、物料、产品和产线是否有效；
- 单位、币种和日期口径是否一致；
- 参数是否在允许范围内；
- 必需数据是否完整且未过期；
- 质量、工艺、安全和环保硬约束是否有效。

### 5.4 模型编排

编排服务按场景生成调用顺序。上游模型输出转换为下游模型可识别的模拟输入，禁止把不同快照或不同运行版本的中间结果混用。

### 5.5 结果汇总

结果服务汇总各模块返回的指标、约束、风险、业务对象和版本信息，计算基线与模拟的绝对变化和相对变化，形成风险传导链。

## 6. 功能结构

| 功能 | 说明 |
|---|---|
| 场景模板 | 提供三个预置场景，展示场景说明和两个变量 |
| 基线快照 | 展示快照编号、截止时间、组织、时域、计划版本和数据质量 |
| 推演时域 | 支持未来 7 天和未来 14 天切换，切换后按新时域重新运行 |
| 对象选择 | 按用户权限选择客户、产品、供应商、物料或产线 |
| 参数设置 | 使用滑块调整两个变量，显示默认值、模拟值、单位和范围 |
| 参数恢复 | 恢复当前场景模板默认参数 |
| 模拟运行 | 显示模型调用步骤、进度、成功、失败或取消状态 |
| 关键结果 | 展示风险日期、产量缺口、到货变化和受影响订单 |
| 趋势分析 | 展示基线、模拟库存曲线和安全库存线 |
| 逐日推演 | 通过时间滑块、图表点击或自动播放，逐日查看生产/到货、库存、安全线差值和业务影响 |
| 影响明细 | 展示受影响供应商、采购单、产线、排程、产品和客户订单 |
| 指标对比 | 展示基线值、模拟值、绝对变化和改善或恶化方向 |
| 影响链 | 按时间和业务关系展示跨模块传导过程 |
| 情景比较 | 比较同一场景不同参数，或比较不同场景的核心指标 |
| 结果导出 | 导出带“模拟结果”标识的分析报告 |
| 审计记录 | 记录快照、参数、运行、查看、比较和导出操作 |

## 7. 场景一 客户增单与交期变化

### 7.1 业务问题

某客户临时增加订单或要求提前交付时，当前产能、库存和原料能否支持，最终会影响哪些订单。

### 7.2 业务对象

- 客户；
- 成品；
- 关联销售订单；
- 成品对应产线；
- 成品对应原材料。

### 7.3 可调变量

| 变量 | 单位 | 建议范围 | 示例 |
|---|---|---|---|
| 订单数量变化 | % | -30%～+50% | +20% |
| 要求交付提前 | 天 | 0～7 天 | 2 天 |

### 7.4 上游输入

| 数据 | 主要来源 | 用途 |
|---|---|---|
| 客户与产品主数据 | 统一数据服务层 | 确定客户、产品和组织范围 |
| 销售订单与承诺交期 | CRM、SAP | 形成订单基线 |
| 需求预测与销售计划 | 需求计划服务 | 形成未明确订单日期的需求基线 |
| 已发布排程和计划入库 | 生产排程、MES | 判断产能和成品入库时间 |
| 产线能力和生产日历 | 生产排程、MES | 计算负荷和完工时间 |
| 成品可用库存 | SAP、WMS | 形成库存水位起点 |
| 已分配、冻结、待检库存 | WMS、QMS、LIMS | 计算实际可用库存 |
| 成品安全库存 | 成品库存优化模块 | 判断越线日期 |
| 产品物料清单和单耗 | 配方、生产基础数据 | 计算模拟原料需求 |
| 采购承诺与原料库存 | 采购模块、SAP、WMS | 评估新增原料缺口 |
| 成本和费率 | 成本核算模块、SAP | 汇总生产、采购、库存和延期成本 |

### 7.5 处理逻辑

```text
订单数量和交期变化
→ 排程模块重算产线负荷、生产顺序和完工日期
→ 成品库存模块使用模拟需求和计划入库计算每日库存
→ 排程或物料需求服务计算模拟原料需求
→ 采购模块评估现有采购承诺后的原料缺口
→ 成本模块汇总增量成本
```

每日库存基本关系：

```text
当日预计库存 = 上日预计库存 + 当日模拟入库 - 当日模拟需求
```

### 7.6 输出

- 模拟订单数量和交付日期；
- 关键产线负荷率；
- 预计完工和计划入库日期；
- 成品库存逐日曲线；
- 安全库存越线日和预计缺货日；
- 模拟原料需求和采购缺口；
- 受影响订单和最大延期天数；
- OTD、最低库存和总运营成本变化。

### 7.7 典型影响链

```text
客户订单增加20%且交期提前2天
→ 关键产线负荷上升
→ 计划入库与提前交付之间出现缺口
→ 成品库存提前跌破安全线
→ 原料模拟需求增加
→ 后续客户订单存在延期风险
```

## 8. 场景二 供应商到货延迟

### 8.1 业务问题

关键供应商延期或可供量下降时，原材料能够支撑到哪一天，哪些生产计划和客户订单会受到影响。

### 8.2 业务对象

- 供应商；
- 原材料；
- 采购订单和到货计划；
- 使用该原料的产线和产品；
- 关联生产计划和客户订单。

### 8.3 可调变量

| 变量 | 单位 | 建议范围 | 示例 |
|---|---|---|---|
| 到货延迟天数 | 天 | 0～14 天 | 7 天 |
| 可供量下降 | % | 0%～100% | 50% |

### 8.4 上游输入

| 数据 | 主要来源 | 用途 |
|---|---|---|
| 供应商和物料主数据 | 统一数据服务层 | 确定供应关系和组织范围 |
| 采购订单与交货计划 | E采、SAP | 形成计划到货基线 |
| 发货和在途状态 | 供应商协同、TMS | 判断到货承诺和在途可信度 |
| 当前原料可用库存 | SAP、WMS | 形成原料库存起点 |
| 原料安全库存 | 库存策略或业务配置 | 判断原料风险水位 |
| 生产消耗计划 | 生产排程、物料需求服务 | 形成逐日原料消耗 |
| 供应商可供量 | 采购模块、供应商协同 | 采购模拟约束 |
| 备用供应商、报价和提前期 | 采购优化模块 | 评估替代来源和成本 |
| 生产排程和订单关系 | 生产排程、CRM | 识别受影响计划和订单 |
| 运费、加急费和采购成本 | 采购模块、TMS、成本模块 | 计算替代采购成本 |

### 8.5 处理逻辑

```text
模拟到货日 = 原计划到货日 + 延迟天数
模拟可供量 = 原计划到货量 ×（1 - 可供量下降比例）
当日预计原料库存 = 上日预计库存 + 当日模拟到货 - 当日计划消耗
```

跨模块传导：

```text
供应商延期和减量
→ 采购模块调整受影响周期的可供量和到货时间
→ 模拟到货结果成为排程的原料可用约束
→ 生产计划和完工时间发生变化
→ 成品入库与客户交付受到影响
→ 汇总替代采购、加急运输和延期成本
```

### 8.6 输出

- 原计划和模拟到货日期；
- 原计划和模拟到货数量；
- 原材料逐日库存曲线；
- 原料安全库存越线日和预计缺料日；
- 采购模拟缺口；
- 受限生产计划和影响数量；
- 受影响客户订单和延期天数；
- 替代采购、加急运输和总成本变化。

### 8.7 典型影响链

```text
主力供应商延期7天且可供量下降50%
→ 原计划到货承诺后移
→ 原料库存跌破安全线
→ 相关产线因缺料受限
→ 成品完工和入库后移
→ 客户订单出现延期风险
```

## 9. 场景三 生产能力下降

### 9.1 业务问题

某条产线在一定时间内产能下降时，计划产量会减少多少，现有成品库存能够支撑到哪一天，哪些订单可能延期。

### 9.2 业务对象

- 工厂和产线；
- 产线生产的产品；
- 已发布排程和生产任务；
- 成品库存和安全库存；
- 关联客户订单。

### 9.3 可调变量

| 变量 | 单位 | 建议范围 | 示例 |
|---|---|---|---|
| 产能下降比例 | % | 0%～60% | 30% |
| 影响持续时间 | 天 | 0～5 天 | 2 天 |

### 9.4 上游输入

| 数据 | 主要来源 | 用途 |
|---|---|---|
| 工厂、产线和产品主数据 | 统一数据服务层 | 确定产线与产品关系 |
| 设备状态和故障事件 | MES、实时数据平台 | 形成产能变化依据 |
| 标准产能和班次日历 | 生产排程、MES | 形成有效产能基线 |
| 维护计划和不可用时段 | EAM、MES | 识别已知产能占用 |
| 已发布排程和工单 | 生产排程、MES | 形成正式计划基线 |
| 实际进度和预计完工 | MES | 判断剩余工作量和入库时间 |
| 成品可用库存 | SAP、WMS | 形成库存水位起点 |
| 计划出库和销售订单 | CRM、SAP | 形成逐日需求 |
| 成品安全库存 | 成品库存优化模块 | 判断库存越线日期 |
| 加班、恢复和延期成本 | 成本核算模块 | 汇总成本影响 |

### 9.5 处理逻辑

目标系统应由有限能力排程模型基于产能日历、订单、工艺和物料约束重新计算。静态 DEMO 使用简化的确定性逻辑演示变量和结果之间的关系：

```text
计划产量缺口 = 基线计划产量 × 产能下降比例 × 影响持续系数
模拟有效产出 = 基线计划产量 - 计划产量缺口
当日预计成品库存 = 上日预计库存 + 当日模拟入库 - 当日需求
```

跨模块传导：

```text
产能下降
→ 排程模块重算有效产出和预计完工
→ 成品库存模块重算计划入库和每日水位
→ 识别受影响订单和预计延期
→ 成本模块汇总恢复生产、加班和延期损失
```

### 9.6 输出

- 模拟有效产能；
- 计划产量缺口；
- 产线负荷和预计恢复日期；
- 模拟完工和计划入库日期；
- 成品库存逐日曲线；
- 安全库存越线日和预计缺货日；
- 受影响客户订单数量和延期天数；
- 恢复生产、加班和延期成本变化。

### 9.7 典型影响链

```text
关键产线产能下降30%并持续2天
→ 有效产出减少且计划入库后移
→ 成品库存消耗快于补充
→ 库存跌破安全线
→ 后续客户订单进入延期窗口
→ 恢复生产和延期成本增加
```

## 10. 上游数据总览

### 10.1 数据来源关系

| 上游系统或模块 | 主要数据 | 更新要求 | 沙盘用途 |
|---|---|---|---|
| 统一数据服务层 | 组织、物料、产品、客户、供应商、产线等主数据 | 按统一数据服务规则 | 对象识别、编码和权限范围 |
| 实时数据平台 | 设备状态、产线状态、储罐液位、在途状态 | 关键运营数据秒级或准实时 | 快照形成和风险基线 |
| CRM或销售系统 | 销售订单、交付日期、客户优先级、需求计划 | 按订单和计划变化同步 | 需求和交付约束 |
| SAP | 订单、采购、库存、成本和财务权威数据 | 按接口策略同步 | 交易和成本基线 |
| E采或采购协同 | 采购订单、供应商承诺、可供量、报价 | 按采购事件同步 | 供应风险和采购模拟 |
| TMS | 发货、在途位置、预计到达、运费 | 在途状态准实时 | 到货可信度和加急成本 |
| WMS | 可用、分配、冻结、待检和在途库存 | 库存事件实时或准实时 | 库存起点和可用量 |
| MES | 工单、设备状态、产量、进度和完工时间 | 关键状态延迟不超过5秒 | 产能和计划入库 |
| 生产排程模块 | 已发布排程、产能日历、模拟排程、原料需求 | 按排程版本同步 | 产能、完工、订单和物料影响 |
| 成品库存优化模块 | 安全库存、再订货点、目标库存、库存轨迹 | 策略按版本，库存按日或实时 | 越线和缺货判断 |
| 采购优化模块 | 采购需求、供应商分配、模拟缺口、综合成本 | 按计算运行 | 供应和原料缺口评估 |
| 成本核算模块 | 采购、生产、库存、物流、能源和资金成本 | 战略指标不超过1小时 | 统一成本口径 |
| QMS和LIMS | 冻结、待检、放行和质量异常 | 按质量事件同步 | 剔除不可用库存和硬约束 |
| EAM | 检修计划、设备可用状态 | 按维护事件同步 | 产能日历和停机约束 |

### 10.2 数据质量要求

快照应展示：

- 数据完整性；
- 数据及时性；
- 关键字段缺失；
- 不同来源的截止时间；
- 异常数据和处理方式；
- 未接入模块或未评估影响。

必需数据缺失时禁止运行。非关键数据过期但仍允许计算时，必须在结果中持续显示数据质量提示。

## 12. 统一输出设计

### 12.1 结果摘要

- 场景名称和运行编号；
- 风险级别；
- 快照、计划和模型版本；
- 运行状态和结果完整性；
- 最早越线、缺料或缺货日期；
- 受影响订单和计划数量。

### 12.2 核心指标

| 维度 | 指标 |
|---|---|
| 交付 | OTD、受影响订单数、最大延期天数 |
| 生产 | 产线负荷、计划产量缺口、预计完工时间 |
| 库存 | 安全库存、推演期最低库存、越线日、缺货日 |
| 采购 | 模拟原料需求、采购缺口、到货日期和数量 |
| 成本 | 采购、加急、生产恢复、库存和延期成本 |
| 质量 | 数据质量、未评估范围和约束状态 |

每个指标应展示基线值、模拟值、绝对变化、相对变化和变化方向。

### 12.3 趋势与明细

- 生产负荷或到货量与库存水位联动图，上下图共享同一时间轴；
- 可拖动、可播放的逐日时间轴，选中日期与图表定位线、提示框和每日业务影响联动；
- 基线与模拟库存曲线；
- 安全库存线；
- 关键事件时间线；
- 受影响对象清单；
- 跨模块影响链；
- 模型调用状态和警告。

### 12.4 模型输出契约

各模型模拟接口至少返回：

- `status`；
- `model_version`；
- `result_ref`；
- `metrics`；
- `affected_objects`；
- `constraints`；
- `warnings`；
- `data_quality`；
- `runtime`。

## 13. 状态与异常处理

### 13.1 运行状态

统一状态包括：草稿、快照准备中、待校验、运行中、成功、部分成功、失败、已取消和已归档。

不得出现“已采纳”“已发布”“已下发”等正式业务状态。

### 13.2 异常处理

- 参数不合法：禁止运行并定位具体参数；
- 快照未就绪：停留在准备状态，不调用模型；
- 单模块失败：不使用历史结果替代本次结果；
- 部分模块成功：展示可独立解释的结果并标记未评估范围；
- 模型不可行：展示冲突约束，不自动放宽硬约束；
- 用户取消：停止启动新的下游模型，结果标记不完整；
- 数据过期：持续显示截止时间和风险提示。

## 14. 安全隔离与审计

### 14.1 存储隔离

情景参数、模拟中间结果和报告保存在独立沙盘结果库，不写入正式订单、计划、工单和库存策略表。

### 14.2 账号隔离

沙盘模型调用使用专用服务身份，对 SAP、E采、MES、WMS 等正式系统只有读取权限。

### 14.3 接口隔离

沙盘只访问模拟接口和只读查询接口。API 网关禁止沙盘身份访问审批、发布、订单生成和工单下发接口。

### 14.4 标识隔离

页面、接口响应、截图区域和导出报告持续显示：

> 模拟结果，仅供分析，不采纳、不发布、不下发生产。

### 14.5 审计内容

记录创建人、运行人、运行时间、快照、对象、参数差量、模型版本、运行状态、查看、比较和导出操作。

## 15. DEMO 与正式系统边界

当前 HTML DEMO 使用固定 Mock 数据和简化确定性公式，用于验证页面结构、变量交互、风险日期展示和跨模块传导表达。

正式系统建设时：

- 页面结构和业务流程可以复用；
- Mock 数据替换为统一数据服务提供的快照；
- 简化公式替换为采购、排程、库存和成本模块的模拟接口；
- 所有关键日期和影响对象以模型实际结果为准；
- 未接入模块明确显示“未评估”，不得伪造完整结论。

## 16. 蓝图编制建议

最终业务蓝图可以将沙盘推演表达为以下四层：

1. **场景层**：客户增单、供应商延期、生产能力下降；
2. **推演层**：基线快照、变量调整、校验、模型编排、结果汇总；
3. **业务模块层**：采购优化、生产排程、成品库存、成本核算；
4. **数据层**：统一数据服务、实时数据平台及 CRM、SAP、E采、MES、WMS、TMS、QMS 等源系统。

业务蓝图中的主流程建议为：

```text
业务人员选择场景与对象
→ 系统锁定同源数据快照
→ 业务人员调整两个关键变量
→ 系统调用相关模块模拟计算
→ 驾驶舱汇总风险日期、影响对象和指标变化
→ 业务人员形成认知并进行情景比较
```

流程终点为“形成认知与决策参考”，不连接正式方案采纳和生产执行流程。

## 17. 验收关注点

1. 三个场景能够基于指定快照独立运行；
2. 每个场景只有两个可调变量，结果能够解释变量影响；
3. 能够展示越线日、缺料或缺货日以及受影响对象；
4. 原料库存与成品库存口径清晰，不混用；
5. 基线与模拟结果使用同一指标口径和版本；
6. 数据缺失、模型失败和结果不完整均有明确标识；
7. 同一快照和参数能够复现相同结果；
8. 沙盘全过程不修改正式数据、不生成订单或工单；
9. 页面和报告均带有模拟标识；
10. 输入、运行、查看和导出操作可审计追溯。
