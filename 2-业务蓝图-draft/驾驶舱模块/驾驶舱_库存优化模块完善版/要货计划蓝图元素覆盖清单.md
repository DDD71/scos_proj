# 要货计划蓝图元素覆盖清单

| 蓝图或技术方案元素 | Demo落点 | 交互与验收要点 |
|---|---|---|
| 要货基础条件与供应商顺序维护 | 基础条件与顺序 | 有效合同、送货条件、默认顺序、人工调整理由、完整性校验、版本发布 |
| 日度要货计划制定与确认 | 日度要货计划 | 28天数据集、库存投影、系统建议、人工调整、可执行性校验、确认发布 |
| 要货计划下达与执行跟踪 | 下达与执行跟踪 | 下达、供应商承诺、发货、在途、收货、质检、执行偏差 |
| 要货计划滚动调整 | 要货计划滚动调整 | 识别变化、保留固定安排、重算未锁定部分、差异对比、新版本发布 |
| 要货缺口与异常协调 | 缺口与异常协调 | 风险日期、缺口数量、原因、协调方向、责任人、临时措施、闭环或升级 |
| 供应商禁运与解除 | 供应商禁运管理 | 申请、复核、生效、参与资格调整、在途保留、触发滚动调整 |
| 已发布生产耗用或BOM换算 | 日度要货计划输入区 | 默认读取已发布原材料需求；BOM换算仅作为缺失时的备选口径 |
| 合格未冻结库存 | 总览和日度计划 | 仅以可用库存进入库存投影，待检或冻结数量不计入可用量 |
| 已确认、已下达、在途固定到货 | 日度计划与滚动调整 | 固定安排不可被自动重排，预计到货日随执行反馈更新 |
| 合同可安排余量 | 基础条件、计划明细、校验结果 | 新增安排不超过剩余可安排量，不重复扣减固定安排 |
| 默认先签先送 | 基础条件与顺序 | 默认合同排序可查看；人工调整必须填写理由 |
| 一家优先、后序补位 | 日度计划求解器 | 前序供应商可满足则单家安排；不足时记录合同余量、能力、日期或禁运补位原因 |
| 到货贴近需要日 | 日度计划求解器 | 在满足耗用与Buffer前提下延后到货，降低计划期库存 |
| 工厂收货能力 | 日度计划校验 | 逐日汇总固定到货和新增计划，不超过日收货上限 |
| MILP多目标模型 | 模型详情弹窗 | 展示变量、五层目标和硬约束；Demo按相同目标优先级执行构造与校验 |
| 人工锁定、移除和重算 | 日度计划明细 | 修改后默认锁定，移除留痕，重算只处理未锁定安排 |
| 风险不伪装成可执行计划 | 计划校验与异常协调 | 未覆盖数量、风险日期和原因明确展示，阻断时禁止发布或下达 |
| 多物料范围 | 总览和计划物料选择 | 玉米淀粉为完整演示样例，原料、辅料、包材可切换查看 |
| 审计与版本 | 所有子模块 | 保存版本、操作人、时间、理由、输入和校验快照 |
